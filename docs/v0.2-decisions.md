## Architecture and alternatives

Use Python standard library and GitHub REST, customer-run GitHub Actions,
versioned JSON schemas, and a single canonical PR comment containing a compact
brief and machine-readable structured state. Installation produces a reviewable
diff and preserves existing policy adapters. No hosted server or database is
necessary for one-repository advisory usage.

Separate collection/drafting from independent review and privileged publication.
Fetch PR code only as bounded data through the GitHub API; never execute it.
Policy comes from the trusted base revision. Comment commands are parsed as data,
never shell. Provider output can add only labelled interpretation, never evidence,
depth reductions, question resolution or approval. A fresh invocation reviews
model drafting; deterministic review always runs. This is limited independence,
not independent assurance of code correctness.

State is structured even though its transport is a comment. GitHub retains command
provenance and comment edit history; run artifacts retain assessment snapshots
for a bounded period. State size is bounded; exhaustion fails visibly rather than
discarding unresolved questions. Repository administrators can alter comments or
delete artifacts; this is not a tamper-proof compliance ledger.

Rejected: a hosted App/database before a demonstrated need; full raw transcript
collection; mandatory model use; vendor session callbacks without tested APIs;
rebuilding Software Signal Gate. Passport carries evidence and uncertainty; it
does not decide workflow progression.

## UX and sufficiency

Authors supply exceptions and a short handoff; evidence and report drafting are
automatic. None and Light paths avoid the Standard question set. Technical
questions route to active or replacement agents; authority gaps remain human.
No inferred human acceptance is permitted, including during dogfood. Claims about
supported platforms depend on exercised workflows, not adapter filenames.
